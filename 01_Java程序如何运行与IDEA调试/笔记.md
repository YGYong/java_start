# 第一节：Java 程序如何运行与 IDEA 调试

## 1. 本节目标与环境

- 创建并运行 Java 程序，理解源码、编译结果和运行过程。
- 使用断点、单步执行和变量窗口观察程序。
- 区分编译错误、运行时异常和逻辑错误。
- 环境：Windows、IDEA 社区版 2026.1、JDK 21。JDK 安装与版本切换后续单独学习。

## 2. Java 程序如何运行

```text
Main.java → javac 编译 → Main.class → JVM 执行
```

| 名称 | 作用 |
| --- | --- |
| 源代码 | 开发者编写的 `.java` 文件 |
| javac | Java 编译器，检查代码并生成字节码 |
| 字节码 | `.class` 文件中的编译结果，供 JVM 执行 |
| JVM | Java 虚拟机，执行字节码 |
| JDK | Java 开发工具包，包含编译器、JVM 等工具 |
| IDEA | 开发环境，帮助编辑、编译、运行和调试代码 |

IDEA 的运行按钮会组织编译与启动过程。安装 IDEA 后，仍需为 Java 工程配置 JDK。

## 4. main 入口与输出

本节使用标准入口声明：

```java
public static void main(String[] args)
```

| 部分 | 含义 |
| --- | --- |
| public | 方法公开可访问 |
| static | 调用前不需要创建 Main 对象，后续结合类与对象深入学习 |
| void | 方法不返回结果值 |
| main | 此入口形式约定的方法名，不是 Java 关键字 |
| String[] args | 接收命令行字符串参数，本节没有传入参数 |

公开类的类名与文件名要一致，区分大小写：`public class Main` 对应 `Main.java`。

`System.out.println(...)` 向控制台输出内容并换行。字符串使用英文双引号，语句末尾使用英文分号。字符串与数字可以使用 `+` 拼接。

## 5. 本节完成的代码

文件：`01_study_java/src/Main.java`。以下保留实际练习逻辑，省略 IDEA 自动生成的提示注释：

```java
public class Main {
    public static void main(String[] args) {
        // 总任务数 5
        int totalTasks = 5;
        // 已完成数 2
        int completedTasks = 2;
        // 总任务数减去已完成数
        int remainingTasks = totalTasks - completedTasks;

        System.out.println("数量：" + remainingTasks);
    }
}
```

`int` 表示整数类型。变量采用小驼峰命名，当前计算为 `5 - 2 = 3`。

可选的可读性改进：输出改为“剩余任务数：”；注释不用重复写 5、2，避免变量值变更后注释未同步。这些不影响本次代码通过检查。

## 6. 运行与断点调试

运行时点击 `main` 左侧绿色三角，选择运行 Main。调试时使用 Debug 启动，普通 Run 不会因为设置了行断点就自动暂停。

1. 在计算 `remainingTasks` 的行左侧点击，设置红色断点。
2. 以 Debug 启动 Main。
3. 停在计算行时观察变量：`totalTasks = 5`、`completedTasks = 2`。
4. 执行一次 Step Over，停在输出行：`remainingTasks = 3`。
5. Resume Program，输出“数量：3”，程序结束。

**调试执行位置的高亮通常表示下一条将执行的语句。** 停在计算行时该行还未执行；停在输出行时计算已完成，输出还未发生。红色断点标记与当前执行位置高亮不是同一个概念。

Debug 控制台中的 `Connected to the target VM` 与 `Disconnected from the target VM` 是调试器连接和断开 JVM 的信息，不是业务输出，也不必然表示错误。

## 7. 三类错误

| 类型 | 例子 | 排查方式 |
| --- | --- | --- |
| 编译错误 | 漏分号、变量名拼错 | 查看编辑器与 Build 输出 |
| 运行时异常 | 整数除以零 | 查看异常类型、原因和调用栈源码位置 |
| 逻辑错误 | 应该减却写成加、使用了错误数据 | 对照业务要求，用断点观察数据与执行路径 |

### 实验一：漏分号

临时移除 `int totalTasks = 5;` 的分号后，编译失败。实际提示为 `java: 需要';'`，位置是 `Main.java` 第 6 行。

编译器指出的是发现问题的位置；某些错误的根因可能在前一行，例如未闭合的括号。补回分号后恢复。

### 实验二：整数除以零

临时加入：

```java
int divisor = 0;
System.out.println(remainingTasks / divisor);
```

实际运行信息：

```text
Exception in thread "main" java.lang.ArithmeticException: / by zero
    at Main.main(Main.java:13)

Process finished with exit code 1
```

- `ArithmeticException`：算术异常。
- `/ by zero`：除数为零。
- `Main.main`：发生在 Main 类的 main 方法。
- `Main.java:13`：这次实验对应的源码位置，修改文件后行号可能变化。

IDEA 已提前给出 `Division by zero` 警告，但这段使用变量的代码仍能编译，执行整数除法时才抛出异常。Java 整数除以零与 JavaScript 普通数字除以零的行为不同。

点击控制台源码位置可以定位代码。实验后删除临时代码，恢复原来的输出。本次已检查磁盘上的恢复代码，未另行执行恢复后的程序。

## 8. 退出码能说明什么

`exit code 0` 表示进程按成功状态结束；本节正常程序走到了结束位置。

它无法证明业务结果正确。例如把 `totalTasks - completedTasks` 写成加法，结果是 7，程序仍可能正常结束。运算符写错只是逻辑错误的一种，错误输入、错误条件、遗漏步骤也可能导致结果不正确。

验证应同时检查：程序能否运行、是否有异常、实际结果是否符合业务预期。

## 9. 常用操作与快捷键

以下按默认 Windows 键位说明，具体以 Settings → Keymap 为准。

| 操作 | 快捷键 | 替代入口 |
| --- | --- | --- |
| 运行选定配置 | Shift + F10 | Run 按钮 |
| 调试选定配置 | Shift + F9 | Debug 按钮 |
| 设置或取消行断点 | Ctrl + F8 | 点击代码左侧断点区域 |
| 单步跳过 | F8 | Debug 窗口 Step Over |
| 继续执行 | F9 | Debug 窗口 Resume Program |

本节无需额外插件。

1. `.java` 和 `.class` 各自是什么？哪一个应该由你修改？
2. 为什么只安装 IDEA 还需要配置 JDK？

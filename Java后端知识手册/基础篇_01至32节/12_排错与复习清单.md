# 12 排错与复习清单

## 一页重点速记

| 【重点记住】 | 优先检查 |
| --- | --- |
| 编译失败 | 首个编译错误、import、依赖、JDK、包路径 |
| 启动失败 | 根因、Caused by、端口、Bean及映射冲突 |
| 根本连不上 | 进程、主机和端口；可能没有HTTP响应 |
| 400 / 404 / 405 / 415 | 参数 / 路径与资源 / 方法 / Content-Type |
| 500 | 后端异常栈和根因，不只看前端“失败”提示 |
| 数据结果不对 | 启动了哪个副本、内存还是数据库、条件与实际行 |
| 排错原则 | 先复现和缩小范围，一次修改一个有依据的原因 |
| 验证闭环 | 源码合理 + 运行结果 + 数据对照 + 能解释原因 |

**允许查阅：**详细错误码不要求背完；先确定问题在哪一层，再看对应章节。

## 详细图文说明

## 1. 【重点记住】排错先定位发生在哪一层

| 现象 | 先检查 | 常见原因 |
| --- | --- | --- |
| 找不到类/无法编译 | import、pom、包路径、SDK | 依赖缺失、导错包、版本配置不符 |
| 工程没有运行入口 | 是否打开正确子工程、源码目录和main | 目录存在但未导入模块 |
| 应用启动失败 | 第一段根因与Caused by | Bean缺失、映射冲突、端口占用、数据库配置 |
| Connection refused | 进程与端口 | 应用未启动或启动失败，无HTTP响应 |
| 404 | URL、方法映射、资源存在性 | 路由不匹配，或业务目标不存在 |
| 400 | 请求参数、JSON、后端校验消息 | 类型转换、缺字段、范围非法 |
| 405 | 请求方法 | 用错GET/POST/PATCH/DELETE |
| 415 | Content-Type与正文格式 | 没按JSON发送 |
| 500 | 后端异常栈 | 空指针、数据库访问失败或未处理异常等 |
| 请求200但数据不对 | 实际启动工程、返回值、数据库对照 | 跑错副本、逻辑错、只改内存 |
| 数据库删了但页面仍显示 | 前端状态/缓存与重新查询 | 页面没刷新，不代表数据库没删除 |

不要只凭一个状态码断定唯一根因。404既可能是路由问题，也可能是业务异常映射；结合响应正文和日志判断。

## 2. 【重点记住】数据库排错顺序

```text
服务是否运行 → 主机端口 → 库名 → 用户与权限 → 驱动与连接配置
→ SQL语法 → 参数绑定 → 表结构与约束 → 结果映射 → 业务判断
```

| 提示/现象 | 检查方向 |
| --- | --- |
| Access denied | 账号、密码、来源主机与授权 |
| Unknown database / table doesn't exist | 库名、当前连接与表名大小写 |
| SQL语法错误 | 真正执行的SQL、逗号、字段类型顺序、关键字 |
| Duplicate entry | 主键或唯一约束，不一定只是id |
| Column cannot be null | NOT NULL与输入字段映射 |
| Parameter not found | @Param与#{}名称是否匹配 |
| id没有回填 | 自增、生成键配置、keyProperty、对象可写属性 |
| 更新0行 | WHERE是否匹配、是否已是目标值、驱动计数配置 |
| 删除0行 | 是否无匹配目标，不能把更新状态的歧义照搬过来 |

先看错误消息和根因，再改配置；不要靠复制一大串连接参数碰运气。

## 3. 【重点记住】工作中高频语法总表

| 场景 | 先记住的写法 |
| --- | --- |
| 判空后判空白 | `title == null || title.isBlank()` |
| 比较文本 | `"done".equals(status)` |
| 可空真假 | `Boolean`；用前判null |
| 默认列表 | `List<Task> tasks = new ArrayList<>();` |
| 遍历列表 | `for (Task task : tasks) { ... }` |
| 返回结果 | `return result;` |
| 拒绝参数 | `throw new IllegalArgumentException("原因");` |
| 业务不存在 | `throw new TaskNotFoundException("原因");` |
| 构造器依赖 | `private final Repository repository;`，构造器赋值 |
| JSON参数 | `@RequestBody CreateTaskRequest request` |
| 路径编号 | `@PathVariable("id") int id` |
| 可选查询参数 | `@RequestParam(name="completed", required=false) Boolean completed` |
| 参数化SQL | `WHERE id = #{id}`，配合@Param |
| SQL状态修改 | `UPDATE task SET completed = TRUE WHERE id = 6;` |
| SQL删除 | `DELETE FROM task WHERE id = 6;` |
| 分页偏移 | `(long) (page - 1) * size` |

## 4. 【常用查阅】最小有效验证清单

| 接口 | 正常情况 | 边界情况 | 数据对照 |
| --- | --- | --- | --- |
| 新增 | 返回真实编号与数据 | 缺失/null/空白/超长标题 | 数据库有一条新记录 |
| 按编号查询 | 返回对应任务 | 不存在编号404 | 与实际行一致 |
| 列表筛选 | 单条件与组合条件正确 | 不传条件、无匹配 | 无匹配返回空列表 |
| 分页 | 首、中、末页正确 | 页码非法、大小非法、超末页 | total与筛选数量一致 |
| 更新状态 | true与false都能设置 | null、缺失、重复设置、不存在 | 状态改变且其他字段不变 |
| 删除 | 成功204无正文 | 重复删除404 | 再查404，数据库无该记录 |

这是测试场景参考，不是声称现有工程已逐项运行。新增/删除验证使用专门练习数据，避免误动重要记录。是否需要断点取决于排错问题，不是每个接口都必须单步。

## 5. 自测题与答案要点

| 问题 | 答案要点 |
| --- | --- |
| Java有哪些基本类型？String属于哪类？ | 8种：byte/short/int/long/float/double/char/boolean；String为引用类型 |
| int和Integer什么时候选？ | 非空数值可用int；需要可空或泛型参数用Integer等包装类型 |
| 参数是int为什么还需业务校验？ | 类型保证整数，不保证非负、范围或业务关系 |
| 引用赋值是否复制对象？ | 否，两个变量可能共享同一对象 |
| final列表是否不可修改？ | final不许重新赋值，列表内容能否修改取决于容器 |
| throw和throws区别？ | 抛异常对象与声明可能传播的异常类型 |
| @Service负责自动生成方法吗？ | 否，标记受管理业务组件，方法自己实现 |
| Repository和Mapper区别？ | 一个封装数据访问职责，一个声明具体SQL/映射；可以按项目选择组织方式 |
| RequestParam和RequestBody区别？ | 查询/表单参数绑定与请求体转换 |
| 异常是否自动对应HTTP状态？ | 否，由框架规则、注解或异常处理器等建立映射 |
| 204能否返回JSON true？ | 不应返回正文，需要正文就选合适的其他成功响应 |
| total是否等于items.size？ | 不一定，总匹配数与当前页条数不同 |
| INSERT返回1是否代表主键1？ | 否，行数与生成键不同 |
| 更新0行是否一定不存在？ | 不一定，受驱动计数与目标值是否变化等影响 |
| 删除0行为何不需查询当前状态？ | 没有“仍存在但字段值未变”的更新情形 |
| 抛异常是否能撤销写库？ | 不能自动撤销，需要正确事务边界等机制 |

## 6. 本手册的知识边界

优先掌握每章【重点记住】与“工作中先记这些”。【常用查阅】是频繁会用但允许随查的内容；【扩展参考】用于补齐知识结构，不要求当前一次掌握。

并发、事务一致性、索引调优、认证授权、Bean Validation、日志系统、完整自动化测试和部署等有各自体系，本手册只在相关处交代入口，不把前32节强行扩成整套Java全栈百科。

## 独立练习：先自己完成，再按标准检查

**练习1：定位请求失败。** 在独立练习副本中选一个可用接口，分别故意发送错误路径、错误请求方法和错误JSON/媒体类型；逐个恢复，再读取状态、正文和日志进行定位。

验收：事先预测结果，再记录实际观察；实际状态与预测不同时查清原因，不为了凑状态码改处理器；不把网络连接失败和HTTP500混为一谈。

**练习2：从现象回到原因。** 任选一次真实的编译、参数绑定或数据库错误，整理“如何复现→根因在哪→最小修改→怎样证明修复”的四项短记录。

验收：证据能支持结论；修改针对根因；只运行尚未覆盖的必要场景；没有把聊天过程整段当成知识总结。

## 工作中先记这些

先定位层次，再阅读根因；配置与源码对应实际启动进程；操作一次、验证一次；异常消息是线索不是最终解释；不把编译通过或HTTP成功等同于业务正确。

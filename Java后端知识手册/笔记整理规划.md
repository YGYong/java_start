# 后续笔记怎样整理

课堂、练习与后续笔记以实际工作中常用的语法为主。详细说明覆盖常用写法的用途、模板和易错点；低频语法、内部机制与无关扩展留到实际需要时查阅。

## 1. 先分清课程篇与主题篇

**每节课仍有一篇课程笔记；多节相关课程再合成主题手册。** 课序用于找到某次学习内容，主题用于跨课程查找完整知识，二者并存。

原01～32课程目录中的笔记.md仍保留。基础篇中的12章，是将这32节涉及的内容按知识主题归并：例如第7、14、15、32节都涉及异常，不需要在主题手册中建四篇重复的异常说明。

主题手册统一放在工作区根目录的 `Java后端知识手册/` 中。第1～32节的12章现归入 `基础篇_01至32节/`；后续主题册与基础篇并列，总目录README负责导航。原来的 `Java后端知识手册_01至32节/` 已迁移，不再作为后续读取路径。

| 文档层次 | 解决的问题 | 保存位置 | 更新时间 |
| --- | --- | --- | --- |
| 每课笔记 | 这一课学什么、语法怎么用、怎么独立复习 | 对应课程目录/笔记.md | 该课完成后整理 |
| 主题/阶段手册 | 同一主题的完整分类、常用语法和跨课联系 | Java后端知识手册/下的主题分册，附课程对照索引 | 主题形成闭环或阶段复习时整合 |
| 学习进度 | 现在学到哪、哪些已验证、下次从哪里继续 | 根目录学习进度.md | 有效进展、暂停、结课时更新 |

课程会话仍是一课一个。文档分层不改变教学会话约定。

## 2. 每篇笔记统一使用三段主体

### 第一段：一页重点速记

开头约6～10条高频要点，尽量控制在一个简洁阅读屏/约一页的篇幅，不追求Markdown在所有设备上恰好打印一页。

- 先给【重点记住】的常用语法、选择规则与规范。
- 放可直接识别的短模板或对照表。
- 不把全部详细参数、扩展分类和长示例塞到速记页。

### 第二段：详细图文说明

先用途，再语法模板，再解释每一部分、常见分类、使用示例与易错点。保留【重点记住】【常用查阅】【扩展参考】标记。

图片根据知识选择：类型用分类图，语法用拆解图，对象用引用图，调用用流程图，分页用区间图。每张图配代码或文字解释、语雀上传提示和图片清单。

### 第三段：少量独立练习

每篇/章默认1～2题，以可以自己完成的小任务为主，附练习目标、必要前提和验收标准，不提前给完整实现。先尝试，再按需回查正文；卡住时先提供提示，明确要求示范时再给答案。

练习在独立目录或练习副本中完成，不把原课程源码作为随手试错的对象。练习未提交时不标记已完成；这些题用于复习，不要求因为新增手册就把原来已结课的课程重新补考。

## 3. 每节课结课时具体做什么

1. 在本课目录生成笔记.md，使用“重点速记→详细图文→独立练习”的结构。
2. 保留本课新增知识、必要的相关参考、关键示例和有价值的易错点。
3. 已有完整公共说明可链接到主题手册，但本课速记、当课新语法和必要说明应可独立阅读。
4. 在进度中记录实际练习、验证和理解情况，更新下一步入口及新会话话术。
5. 涉及已有主题时，记录应归入哪个手册章节；主题整合时合并重复内容，修订索引。

课堂问题只提炼成通用易错点。聊天过程、检查轮次和师生约定不作为知识正文。

## 4. 主题手册何时做，不按固定课数凑册

以“知识形成可查用的闭环”为节点，可能是几节课，也可能跨更多课。例如数据库条件查询、动态SQL与分页可以形成一个“数据库查询进阶”主题，而不是每过一课就复制整套基础手册。

主题整合时：

- 将多课同一知识归并为一份完整说明，更新常用语法和易错点。
- 新主题建立新章或新册，已经讲清的基础内容通过索引关联。
- 为每一册写明覆盖课序和知识范围，区分已学习内容与扩展参考。
- 保留课程目录中的原笔记，不因合并主题而删除每课入口。

**当前基础篇固定覆盖第1～32节。** 它是基础阶段汇总，可以做勘误、速记和练习优化；第33节以后的新课程仍各自生成笔记，后续在Java后端知识手册/中按主题形成新的阶段册，基础内容引用基础篇。新主题册的具体范围在该主题完成时确定，不预先把未学习的未来课程写成已完成手册。

不要求每个阶段都重复“Java有哪些类型”等完整基础章节；主题手册负责归纳，课程笔记负责具体入口。

## 5. 示例：后续一课怎样衔接

第三十三节“MyBatis任务筛选与动态SQL”完成后：

- 课程篇保存到33_MyBatis任务筛选与动态SQL/笔记.md，包含动态条件的速记、图文、练习。
- 与本册的Boolean三态、参数绑定等章节建立关联。
- 后续相关查询课程形成闭环时，再整合到数据库查询进阶主题册。

这里只说明整理方式，不提前创建正式第三十三节笔记，也不表示该课已完成。
